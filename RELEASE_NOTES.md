## What's Changed

### New
- **See your label before you commit to it.** Settings › Appearance now has a **Status text** card built around a live preview of the label that sits under the panda. It renders with the same text builder and the same window width as the real desktop label, so where the text gets cut off with a "…" is exactly where it will be cut off on your desktop. Inside the card: the text-size slider (moved here from above, where it sat before the switch that made it matter), a **Show** row where you pick which parts appear — Layers, Time Left, Done At — and a **When Text Overflows** choice. Nine rows of switches are now four, and the pet-size and text-size sliders finally show their effect while you drag them. The preview also follows your system's 12/24-hour setting, so a time in the preview reads the same as the one on your desktop.
- **Copy diagnostics.** Settings › About has a **Copy diagnostics** button that puts this machine's environment on your clipboard in one click: app, Electron and Chromium versions, OS build, GPU model and driver version, GPU feature status, every display's resolution/scaling/color depth/color space and which one the panda is on, window geometry, and the current state. If the panda ever looks wrong on your screen, paste that into your report and it can be diagnosed without a back-and-forth. Anything that can't be read shows up as "(not available)" — the button never fails on you.

### Fixes
- **The panda no longer turns into a black block or a black square on Windows.** Three separate causes, all of them driver-dependent, which is why this could start happening out of nowhere on a version that had been fine for months:
  - Chromium could promote the panda's video to a hardware overlay plane, which the system composites without the window's per-pixel transparency — a solid rectangle punched into a transparent window. It is no longer allowed to do that. The panda is an 80–400px decorative loop, so there was nothing to gain from the overlay anyway.
  - A `backdrop-filter` on the status pill could force the whole window to be treated as opaque on some GPUs. It was doing nothing visible in the first place — it can only sample the page's own background, and there is nothing behind the pill — so removing it changes nothing except the black window.
  - The window's compositing surface is rebuilt whenever it is re-shown or the display setup changes (a fullscreen app comes and goes, you plug in a monitor, change scaling, turn on HDR, wake from sleep), and the first frame after the rebuild could come up opaque black and stay that way. The window now forces a repaint on all of those, including after a resize — which is what made dragging the pet-size slider a coin flip on some machines.
- **Dragging the pet-size slider is smooth again.** Every pixel of slider movement used to resize the transparent window; the window now resizes at most once every 50ms while you drag and settles on the exact size when you let go.
- **Match Filament Color works on dual-nozzle printers again.** Since v0.4.3, dual-nozzle machines (H2D, X2D) read the color from the active nozzle, and any case that couldn't be resolved simply gave up — leaving the panda holding its default green with the switch turned on. Two of those cases are everyday setups: printing from an external spool (common on an H2D with no AMS), and printers that don't report which nozzle is extruding. External spools now read the right tray, a single loaded nozzle is taken as the active one, and anything still unresolved falls back to the single-nozzle path instead of concluding there is no color.

### Improvements
- **The label holds still.** When the text didn't fit, it used to scroll sideways forever — motion in the corner of your eye while you work. Each printer now gets exactly one line that ends in "…" when it runs out of room, so the label never changes height because a name got long or a switch got flipped, and the single-printer window is back to its original height. To read what got cut off, hover the panda or the label and it scrolls once, then stops when you move away. Prefer the old behavior? **When Text Overflows › Scroll always** brings it back. Long printer names no longer push the status off the end of the line either — the name gets at most half the line, because the first few characters are enough to tell which printer it is, and "what's happening" is the part you actually need.

### Under the hood
- The label's text assembly is now a shared pure function used by both the desktop label and the settings preview, so the two cannot drift apart, with tests locking down the exact strings it produces.
- New tests guard the transparent-window defenses themselves: the overlay switch must exist and must be applied before the app is ready, and every path that resizes, re-shows, or moves the window between displays must repaint.
- The label preview script now renders at the real window width and covers multi-printer layouts, so label wording can be checked without a printer or a display.
